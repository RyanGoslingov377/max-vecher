# Мини-приложение

Ванильный HTML/CSS/JS без сборки. Страницу и API раздаёт один сервер, поэтому адреса запросов относительные (`/api/...`).

## Файлы

```
index.html  каркас страницы, подключает MAX Bridge, стили и app.js
app.js      экраны, переходы и действия
api.js      все запросы к серверу (формат — контракт API в CLAUDE.md)
styles.css  оформление: светлая и тёмная тема, цвета настроений
```

## Экраны

1. **Настроение** — 6 плиток (id как в `server/picker.py`).
2. **Настройка** — день (сегодня / завтра / в субботу) и тумблер «Бюджет поджимает» (до 300 ₽). Фон — цвет настроения.
3. **Результаты** — `GET /api/pick`, первое событие выделено «Мы бы пошли сюда». В «Удиви меня» у каждого события подписано его настроение, дорогие при включённом бюджете помечены «дороже 300 ₽».
4. **План** — событие, кнопка «Позвать чат» (`POST /api/invites`) и ссылка на билеты, если есть `ticket_url`.
5. **Приглашение** — живой счётчик «Иду / Может / Не могу»: `GET /api/invites/{id}` раз в 4 секунды, пока экран открыт.

## Как устроен app.js

- `state` хранит всё, что сейчас видно: экран, настроение, день, результаты и т. д.
- `render()` рисует текущий экран заново из `state`. Каждый экран — функция, которая возвращает HTML-строку.
- У кнопок есть `data-action`. Один обработчик кликов смотрит на него и меняет `state`.
- Текст из данных проходит через `esc()`, чтобы его нельзя было выполнить как HTML.

## МАКС

- `window.WebApp` даёт MAX Bridge (скрипт `st.max.ru/js/max-web-app.js`). Внутри МАКС используем `initData` (подпись для сервера), системную кнопку «Назад», `openLink` и `close`.
- В обычном браузере `initData` пустой: своя кнопка «←» рисуется в шапке, а сервер с `DEV_AUTH=1` в `.env` подставляет тестового пользователя.
- Локально бот выключен (`BOT_ENABLED=0`), поэтому после «Позвать чат» приглашение сохраняется, но в чат не уходит. Экран об этом пишет.

## Проверка

Запусти сервер (см. корневой README) и открой http://localhost:3000. Для телефона удобно включить в DevTools режим устройства шириной 360 px.
