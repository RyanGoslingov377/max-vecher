# Вечер по настроению — бот и мини-приложение для МАКС

Помогаем выбрать, куда пойти вечером, по настроению — и позвать друзей одной кнопкой прямо в групповом чате МАКС.
Конкурс МАКС × Минобрнауки, трек «Досуг и развлечения». Город пилота — Казань.

**Проблема.** Люди чаще не «не находят событие», а не могут решиться и не знают, с кем идти. Поэтому вместо афиши с фильтрами — три варианта под настроение и приглашение для друзей, на которое можно ответить в один тап.

## Попробовать

| Что | Где |
| --- | --- |
| Бот | `@t420_hakaton_max_bot` в МАКС |
| Мини-приложение | открывается из бота; сайт: https://max-vecher-gosuslugov233.amvera.io/ |
| Документация API | https://max-vecher-gosuslugov233.amvera.io/docs |
| Метрика | https://max-vecher-gosuslugov233.amvera.io/api/stats |
| Проверка, что бот жив | https://max-vecher-gosuslugov233.amvera.io/api/health |

**Основной сценарий (≈3 минуты):**

1. Напишите боту `/вечер` → нажмите **«Подобрать вечер»** — откроется мини-приложение.
2. Выберите настроение, день и, если хочется, «Бюджет поджимает» → получите три события.
3. Выберите событие → **«Позвать чат»** (или «Отправить себе», если открыли из лички с ботом).
4. В чат придёт карточка события с кнопками «Иду / Может / Не могу». Нажмите — счётчик на карточке и в мини-приложении обновится.
5. Через 2 минуты бот спросит в том же чате «Как прошёл вечер?» — ответ попадёт в метрику `/api/stats`.

**В групповом чате:** сценарий готов, но на момент сдачи организаторы ограничили добавление ботов в общие чаты. Когда это ограничение снимут, достаточно добавить бота в чат администратором и написать `/вечер` — приглашение уйдёт в эту группу. Пока мини-приложение корректно работает из личного чата с ботом.

## Как работает подбор

Это правила, а не ИИ. Каждое настроение и каждое событие описано двумя числами от 0 до 2:

- **энергия** (`nrg`): 0 — тихо, 2 — громко и активно;
- **глубина** (`dep`): 0 — легко, 2 — сильно трогает.

Подбираем события, ближайшие к настроению по этим осям, с бонусом за подходящий формат (например, «музыка и танцы» для «Заряжен(а)»). «Узнать новое» — отдельный фильтр по обучающим событиям, «Удиви меня» — по одному событию из трёх случайных настроений. Тумблер «Бюджет поджимает» поднимает наверх события до 300 ₽, а дорогие помечает. Учитывается выбранный день: регулярные события — по дням недели, прошедшие не показываются.

Код — [server/picker.py](server/picker.py), тесты — [tests/test_picker.py](tests/test_picker.py).

## Что смоделировано

- **События** в [data/events.json](data/events.json) смешанные: разовые события взяты из казанской афиши, а регулярные (`weekly`) и вечерние активности (`anytime`) смоделированы по реальным местам Казани, чтобы подбор не пустел после дат разовых афишных событий. Оплаты внутри приложения нет; для продакшена нужен куратор или партнёрская афиша с API.
- **Оплаты и билетов нет.** Кнопка «Билеты» появляется только у событий со ссылкой на сайт организатора.
- **«Сходили?»** в демо приходит через 2 минуты после приглашения (`FOLLOWUP_DELAY_MIN=2`); в продукте — в полдень следующего дня после события.
- **Цифровой ID** и студенческие скидки не подключены.

## Запуск через Docker

```
copy .env.example .env
docker compose up --build
```

(на macOS/Linux — `cp` вместо `copy`). Поднимутся мини-приложение и API на http://localhost:3000, база — в томе `app-storage`.

По умолчанию бот не запускается (`BOT_ENABLED=0`): он уже работает на хостинге, а бот с одним токеном должен работать в одном месте. Чтобы попробовать защищённые адреса в обычном браузере, поставьте в `.env` `DEV_AUTH=1` — сервер пустит тестового пользователя без подписи МАКС.

## Настройки (.env)

| Переменная | Что значит |
| --- | --- |
| `BOT_ENABLED` | 1 — запускать бота (хостинг), 0 — только сайт и API |
| `MAX_BOT_TOKEN` | токен бота, нужен при `BOT_ENABLED=1`; в репозитории его нет |
| `DEV_AUTH` | 1 — пускать без подписи МАКС тестового пользователя (только локально) |
| `DEV_CHAT_ID` | при `DEV_AUTH=1` — чат для тестовых приглашений |
| `FOLLOWUP_DELAY_MIN` | через сколько минут спрашивать «Сходили?» (демо); пусто — назавтра в 12:00 |
| `MAX_API_URL` | адрес Bot API, по умолчанию `https://platform-api.max.ru` |

## Хостинг

Рабочая версия живёт на [Amvera](https://amvera.ru): платформа собирает тот же `Dockerfile` (настройки — [amvera.yml](amvera.yml)), держит бота запущенным круглосуточно и сама выкладывает новую версию после мёрджа в `main`. База — на постоянном диске `/data`. Токен задан в переменных проекта на Amvera.

## Собственный API

- OpenAPI 3.1: https://max-vecher-gosuslugov233.amvera.io/openapi.json (копия — [openapi.json](openapi.json)).
- Описание, доступы и тестовые данные — [DATA-API.yaml](DATA-API.yaml).
- `/api/me` и `/api/invites` требуют заголовок `X-Max-Init-Data` — подпись МАКС, которую мини-приложение получает при запуске; сервер проверяет её токеном бота ([server/auth.py](server/auth.py)). Остальные адреса открыты.

## Разработка

```
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python -m uvicorn server.main:app --reload --port 3000
```

Тесты — `python -m pytest`. После изменения API — `python -m server.export_openapi` (обновит `openapi.json`, иначе тест напомнит).

```
server/
  main.py            API + раздача мини-приложения, бот в фоне
  bot.py             бот: /вечер, карточки приглашений, кнопки
  followup.py        «Сходили?» и метрика
  picker.py          подбор под настроение
  events.py          чтение и проверка data/events.json
  auth.py            проверка подписи МАКС
  db.py              SQLite
  schemas.py         форматы ответов API
  max_api.py         клиент Bot API МАКС
  config.py          настройки из .env
  export_openapi.py  сохранить openapi.json
web/                 мини-приложение (ванильный JS) — см. web/README.md
data/events.json     события и регулярные вечерние активности для подбора
tests/               автотесты
```

Как работаем вдвоём (ветки, PR, зоны файлов) и контекст для ИИ-помощника — в [CLAUDE.md](CLAUDE.md).
