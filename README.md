# max-vecher

Мини-приложение и бот для МАКС: подбираем вечер по настроению и зовём друзей карточкой «Иду / Может / Не могу» в групповом чате. Конкурс МАКС × Минобрнауки, трек «Досуг и развлечения».

Подробно про продукт, подбор и план — в документе команды: https://claude.ai/code/artifact/a21cfe51-a584-4ae4-8d55-b5dbe6b33651 (попроси доступ у капитана). Задачи и роли — во вкладке «План и задачи». Контекст для Claude — в [CLAUDE.md](CLAUDE.md).

## Что сейчас работает

- Бот `@t420_hakaton_max_bot` отвечает на `/help` и `/вечер`.
- `/вечер` присылает тестовую карточку с кнопками, счётчик обновляется при нажатии. Ответы хранятся в SQLite (`data/app.db`).
- Подбор событий: http://localhost:3000/api/pick?mood=charged&day=saturday&budget=1
  - `mood`: charged, release, exhale, blue, learn, wild
  - `day`: today, tomorrow, saturday
- `GET /api/me` — кто открыл мини-приложение. Подпись МАКС проверяется на сервере, без неё — ошибка 401.
- В `data/events.json` пока **выдуманные примеры** событий — их заменят на реальные (задача К1).

## Первый запуск (один раз)

Нужны Git и Python 3.12. В терминале, в папке проекта:

```
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Потом открой `.env` и поставь `BOT_ENABLED=0` и `DEV_AUTH=1`: сервер запустится без бота, токен не нужен. Живой бот работает на хостинге (см. «Хостинг»).

На macOS/Linux вместо первых двух строк: `python3.12 -m venv .venv` и `source .venv/bin/activate`, вместо `copy` — `cp`.

## Каждый запуск

```
.venv\Scripts\activate
python -m uvicorn server.main:app --reload --port 3000
```

Остановить — `Ctrl+C`. В логе будет `Бот выключен (BOT_ENABLED=0)` — так и должно быть локально.

## Запуск через Docker

Нужен Docker. В папке проекта:

```
copy .env.example .env
docker compose up --build
```

В `.env` впиши `MAX_BOT_TOKEN`. Сервер и бот поднимутся на http://localhost:3000, база хранится в томе `app-storage`.

## Хостинг

Рабочая версия: https://max-vecher-gosuslugov233.amvera.io/ (проверка: `/api/health`, документация API: `/docs`).

Она живёт на [Amvera](https://amvera.ru): платформа собирает тот же `Dockerfile` (настройки — в `amvera.yml`) и держит бота запущенным круглосуточно. База лежит на постоянном диске `/data`. Токен бота задан в переменных проекта на Amvera, в репозитории его нет.

Пока бот работает на хостинге, локально его не запускаем: у всех в `.env` стоит `BOT_ENABLED=0`.

## Структура

```
server/
  main.py     веб-сервер, API + запуск бота
  auth.py     проверка подписи МАКС: кто открыл мини-приложение
  bot.py      обработка сообщений и кнопок
  picker.py   подбор событий под настроение
  events.py   чтение и проверка data/events.json
  db.py       база SQLite
  max_api.py  запросы к Bot API МАКС
  config.py   чтение .env
data/
  events.json события от куратора
web/          мини-приложение (пока заглушка)
tests/        автотесты
```

## Тесты

```
python -m pytest
```

Запускайте после каждой правки `data/events.json` — тест покажет, какое событие заполнено неправильно.

## Как работаем вдвоём

Прямо в `main` не пушим: одна задача — одна ветка — один PR. У каждого файла один хозяин (бэкенд или фронт), поэтому PR не конфликтуют. На каждом PR GitHub сам запускает тесты и сборку Docker. Подробные правила — в разделе «Ветки и PR» в [CLAUDE.md](CLAUDE.md).
